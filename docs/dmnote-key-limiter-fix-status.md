# DM Note 키 리미터 수정 상태

2026-09-09

## 문제 2: 백슬래시 제한 — macOS 코드 수정 완료

설치된 SkyHook 네이티브 라이브러리를 직접 조회했다. macOS HID 코드 `0x31`과 `0x64`는 모두 같은 백슬래시 라벨로 변환되지만, 라벨에서 물리 코드로 역변환하면 `0x31`만 반환된다. 기존 리미터는 역변환 결과 하나만 허용하여 `0x64` 입력을 차단했다.

`DmNoteKeyMapper.AddAsyncKeys`에서 macOS 백슬래시에 두 코드를 모두 허용하도록 수정하고 `KeyLimiterService`에 적용했다. `BACKSLASH`와 문자 `\` 등록, ANSI/ISO 입력 허용, 별개인 슬래시 차단, 다음 동기화에서 백슬래시를 제거했을 때 재차단하는 테스트를 추가했다.

소스 수정과 테스트까지 완료했다. 실행 중인 게임에 모드를 재설치하거나 실제 키보드로 플레이하면서 확인한 것은 아니다. Windows 환경에서 같은 증상이 발생했다면 별도 확인이 필요하다.

## 문제 1: 발 탭 선택 후 손 키뷰어 일부 입력 누락 — 재현 및 수정 완료

원인은 `migration.rs`의 `ensure_viewer_tabs`였다. 이 함수는 초기 마이그레이션뿐 아니라 `AppStore.update`를 통한 모든 저장에서 호출된다. 손 탭을 검증할 때 손의 선택값 대신 전역 편집 탭인 `selected_key_type`을 사용했다. 발 탭 선택 후에는 그 값이 발 탭이므로 손 탭을 찾지 못하고 목록의 첫 손 탭(`inroll`)으로 되돌렸다.

프런트엔드는 발 변경 이벤트에서 발 선택값만 병합하므로 손 화면은 numpad를 유지했다. 그 결과 화면과 백엔드 입력 판정 탭이 달라져, 첫 손 탭에도 등록된 키만 반응했다. 알려준 LShift·RAlt가 첫 손 탭에 있고 A·J·방향키·넘패드가 없는 패턴과 일치한다.

손 선택값을 `selected_viewer_tabs.hand`에서 우선 검증하도록 수정했다. 유효한 손 선택이 없을 때만 편집 탭과 첫 손 탭으로 대체한다. 이전 버전 데이터는 최초 마이그레이션 시에만 편집 탭을 손 선택값으로 옮겨 호환성을 유지한다.

실제 `AppStore.update` → 정규화 → 파일 저장 → 재로드 경로를 테스트에 추가했다. 수정 전에는 `numpad` 대신 `inroll`이 나와 실패했고, 수정 후에는 손→발 및 발→손 선택 순서 모두 통과했다. 다른 설정 저장 후에도 선택이 유지된다. 이전 검증은 저장 이후 정규화 단계를 빠뜨려 이 문제를 잡지 못했다.

실제 키보드를 이용한 화면 확인은 아직 수행하지 않았다.

macOS 릴리스 앱 빌드 및 코드 서명 검증을 완료했다. 실행 파일은 `apps/element-note/src-tauri/target/release/bundle/macos/ElementNote.app`이다. 실행 중인 DM Note를 완전히 종료한 후 이 앱을 실행하면 문제 1 수정이 적용된다. 문제 2 수정은 별도의 게임 모드 DLL 변경이므로 앱 실행만으로 적용되지는 않는다.
