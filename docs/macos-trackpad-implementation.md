# macOS 레벨 에디터 트랙패드 — 첫 구현

**2026-10-05: 비활성 창 입력 수정**

- Unity의 `Application.isFocused`와 네이티브 모니터의 `NSApp.active`·`isKeyWindow` 조건을 제거했다. AppKit이 게임 창에 전달한 정밀 스크롤·핀치 이벤트는 창을 먼저 클릭하지 않아도 처리한다. 입력 수집은 앱의 로컬 모니터를 사용한다. [Apple의 로컬 이벤트 모니터 문서](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents(matching:handler:))
- 비활성 창에서 Unity의 `Input.mousePosition`이 오래된 좌표일 수 있으므로, 네이티브 핀치를 적용하는 동안 `ZoomCamera`의 최초 포인터 읽기를 이벤트 좌표로 대체한다. 일반 게임 줌은 기존 좌표를 사용한다.
- 캔버스/UI 대상 구분, 관성, 편집 상태에 따른 차단은 유지한다. 포커스 전환만으로 제스처 소유권을 초기화하지 않는다.
- 설치된 AdofaiIpc Bootstrap의 체크섬이 lock 파일과 달라 첫 빌드가 중단됐다. lock 파일과 SHA-256이 일치하는 로컬 `adofai-ipc/build/package`의 Bootstrap·DependencyShim을 빌드 입력으로 지정해 `./scripts/run.sh build`를 완료했다.
- arm64/x86_64 네이티브 빌드와 C# 모드 빌드 성공, 모드 경고·오류 0개, 기존 트랙패드 검사를 포함한 C# 테스트 14개 그룹 통과. `./scripts/run.sh check`의 셸 스크립트 22개 구문 검사와 `git diff --check`도 통과했다. NuGet 취약점 조회 경고(NU1900)가 있었고 shellcheck는 설치되어 있지 않다.
- 수정한 DLL·dylib를 로컬 게임 모드 폴더에 설치했으며 빌드 출력과 설치 파일의 SHA-256 일치를 확인했다. **게임 재시작이 필요하다.** 비활성 창에서의 실제 두 손가락 패닝·핀치와 최신 Harmony 줌 패치의 런타임 적용은 아직 실기 검증하지 않았다.

2026-09-09. 두 손가락 패닝·핀치 줌을 구현하고 로컬 ADOFAI 모드 폴더에 설치했다. **현재 실행 중인 게임을 재시작하면 최신 수정이 적용된다.**

사용자가 첫 빌드에서 좌우 패닝이 정상이며 위아래 패닝은 반대라고 확인했다. 이에 AppKit의 세로 스크롤 이동량을 Unity의 아래에서 위로 증가하는 화면 좌표에 맞춰 반전했다. 가로 방향은 유지했다. 수정한 네이티브 라이브러리까지 다시 빌드하고 설치했다. 수정 후 세로 방향과 실제 핀치 감각은 추가 실기 확인이 필요하다.

**사용 방법**

- 편집 모드의 캔버스 위에서 두 손가락으로 이동하면 패닝한다. OS의 관성 스크롤도 같은 대상에 적용한다.
- 핀치를 벌리면 확대, 오므리면 축소한다. 게임의 포인터 기준 줌 함수를 즉시 적용 모드로 사용한다.
- 일반 마우스 휠은 기존 게임 처리를 유지한다. 정밀 스크롤을 제공하는 Magic Mouse는 트랙패드와 같은 패닝 경로에 들어갈 수 있다.
- UnityModManager의 ImplResourcePack 설정에서 `Level editor → Native trackpad (two-finger pan / pinch zoom)`으로 끌 수 있다. macOS에서는 기본 활성화다.
- 재생 모드, 입력 필드 편집, 설정·파티클 편집 패널, 팝업 및 마우스 버튼 드래그 중에는 네이티브 카메라 제스처를 적용하지 않는다.

**변경 내용**

- [네이티브 입력 모듈](../native/macos/Trackpad.mm): AppKit의 정밀 스크롤과 magnify 이벤트를 별도로 수집한다. 제스처 단계와 관성 단계를 보존하고, 창 크기에 대해 정규화한 좌표와 이동량을 C ABI로 전달한다. bounded queue가 넘치면 해당 입력을 취소한다.
- [네이티브 로더](../ImplResourcePack/Infrastructure/Game/Editor/MacTrackpadNative.cs): 모드 폴더의 라이브러리를 절대 경로로 로드한다. 모드 해제 시 이벤트 모니터를 제거한다.
- [에디터 연결](../ImplResourcePack/Infrastructure/Game/Editor/EditorTrackpadController.cs): 캔버스와 UI의 제스처 대상을 구분한다. 에디터 Update의 기존 휠 읽기와 Unity UI 스크롤 경로를 제한적으로 패치해 중복 처리를 막는다. 오류나 API 변경에는 네이티브 기능을 해제하고 원래 입력으로 복귀한다.
- [제스처 상태·줌 계산](../ImplResourcePack/Infrastructure/Game/Editor/TrackpadGesture.cs): 손을 떼고 관성이 이어져도 대상을 유지한다. 취소된 캔버스 관성이 UI 스크롤로 전환되지 않도록 처리한다. 작은 핀치 입력은 연속 배율로 반영한다.
- macOS 빌드에 arm64/x86_64 universal dylib 컴파일과 ad-hoc 서명을 추가하고 설치·패키징에 포함했다.
- `scripts/tasks/install/mod.sh --runtime-only`는 실행 중인 게임이 읽는 바이너리를 직접 덮어쓰지 않고 새 파일을 rename으로 교체한다. 새 코드는 게임 재시작 후 적용된다.

**검증 결과와 범위**

| 확인 항목 | 결과 |
|---|---|
| Objective-C++ 네이티브 모듈 | arm64/x86_64 빌드 통과, `-Wall -Wextra -Werror` 적용 |
| C# 모드 | 최종 빌드 성공, 경고 0·오류 0 |
| C# 테스트 | 기존 테스트와 새 제스처 테스트 포함 8개 테스트 그룹 통과 |
| 제스처 회귀 검사 | UI/캔버스 대상 유지, 관성, 취소 후 복구, 작은 핀치 누적, 확대 한계에서 역방향 반응, 비정상 확대량, native ABI 크기·offset 확인 |
| 쉘 스크립트 | 22개 구문 검사 통과. shellcheck는 설치되어 있지 않아 미실행 |
| 실제 게임 시작 | `macOS editor trackpad ready: two-finger pan and pinch zoom.` 로그 확인. 최초 설치 빌드의 네이티브 로딩·Harmony 적용 정상 |
| 실제 패닝 | 사용자 확인: 최초 빌드 가로 정상, 세로 반대. 세로 부호 수정 후 재빌드·설치 완료 |
| 설치 파일 | 최종 DLL과 dylib의 SHA-256이 빌드 출력과 일치 |

테스트 실행 시 NuGet 취약점 조회 서버에 접근하지 못했다는 NU1900 경고가 있었다. 테스트 자체는 모두 통과했다. 네이티브 로딩 로그는 최종 세로 부호 수정 이전 실행에서 확인한 것이며, 최신 파일은 실행 중인 프로세스를 재시작해야 로드된다.

실제 핀치, 수정 후 세로 패닝, Retina/외부 모니터, UI 경계 통과 중 관성은 아직 실기 검증을 완료하지 않았다. 자동화 도구의 마우스·키 입력으로는 게임 메뉴 이동을 확인하지 못했다. 게임 종료는 자동 승인 검토에서 미저장 상태 손실 가능성을 이유로 거절되어 진행하지 않았고, 실행 상태를 유지하면서 바이너리만 교체했다.

현재 구현은 프레임별 기존 휠 값을 억제한다. 마우스 휠과 트랙패드 스크롤을 정확히 같은 프레임에 동시에 사용하면 해당 프레임의 마우스 휠 입력도 생략될 수 있다. 순차적인 마우스·트랙패드 병용과 별도로 남은 경계 사례다.

**다음 실기 확인**

1. 게임 재시작 후 캔버스에서 위·아래·좌·우 이동이 손가락 방향과 자연스러운 스크롤 설정에 맞는지 확인한다.
2. 포인터를 타일 위에 두고 핀치했을 때 타일이 포인터 아래에 유지되는지 확인한다.
3. 패널에서 시작한 스크롤이 캔버스로 넘어가도 카메라를 움직이지 않는지, 캔버스 관성이 패널을 스크롤하지 않는지 확인한다.
4. 설정에서 기능을 끈 뒤 기존 휠 줌과 Ctrl+휠 재생 속도 변경이 동작하는지 확인한다.
