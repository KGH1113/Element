# 게임 내 네이티브 키뷰어

게임 내 키뷰어는 macOS 11 이상(WKWebView)과 Windows 10 이상(WebView2)에서
네이티브 웹뷰로 렌더링합니다. 기존 이미지 미러는 제거했으며 Linux는 아직
지원하지 않습니다.

## 동작

ElementNote의 OBS 브릿지가 손·발 페이지의 인증된 loopback URL과 원본 논리
뷰포트 크기를 제공합니다. 게임 모드가 네이티브 라이브러리를 로드하고 실제
Unity 창의 `contentView` 안에 추가된 손·발 요소마다 투명한 WKWebView를 붙입니다. 별도 앱 창은
생성하지 않습니다. 웹뷰는 입력과 포커스를 받지 않아 게임 조작을 통과시킵니다.

Windows에서는 게임 프로세스가 같은 페이지를 WebView2 Composition 컨트롤러로
열고, Unity 창에 붙인 맨 위 DirectComposition 레이어에 합성합니다. 여기서도
별도 창을 만들지 않고 입력을 전달하지 않으므로 클릭·키 입력과 키보드 포커스는
게임에 그대로 갑니다. 페이지의 스크립트·레이아웃·래스터화는
`msedgewebview2.exe` 프로세스에서 실행되고 게임은 그 결과를 그리지 않습니다.
시스템의 Microsoft Edge WebView2 런타임(Windows 11 기본 포함)을 사용하며, 없으면
편집 화면의 키뷰어 예시에 설치 안내를 표시합니다. 쿠키와 저장소는 InPrivate로
남기지 않습니다. 렌더러나 브라우저 프로세스가 종료되면 1초 뒤 페이지를 다시
만들고(1분에 최대 5회), 게임 세션이 끝난 뒤에도 WebView2 환경과 그래픽 장치를
60초 동안 유지해 일시정지·재시작 뒤 다시 붙일 때 바로 표시합니다. 처음 붙일 때는
게임 스레드에서 약 40ms, 이후 다시 붙일 때는 약 3ms가 걸리며, 플레이 중에는
프레임마다 창 크기 확인만 합니다.

이 모드에서는 게임이 이미지 캡처를 요청하지 않습니다. 파일 읽기·쓰기와
Unity 텍스처 업로드도 없습니다. 앱은 OBS 모드·토큰·포트나 리플레이 렌더링
상태가 바뀔 때 `mirror.native.changed`·`mirror.native.unavailable` 이벤트로
URL·크기·뷰어 구성을 알리고, 게임은 놓친 이벤트에 대비해 30초마다 한 번만
확인합니다. `mirror.available`에 `nativePush`가 없는 이전 앱에는 2초마다
확인합니다. 화면 애니메이션은 웹뷰가 직접 그립니다. 같은 구성을 다시 받으면
네이티브 레이아웃과 페이지를 건드리지 않습니다. 앱이 바쁘거나(`mirror-busy`)
OBS 서버가 시작 중이면(`obs-not-ready`) 페이지를 유지한 채 다시 시도하고,
리플레이 렌더링 중에는 숨깁니다. OBS가 꺼지거나 앱 연결이 끊기면 웹뷰를
제거하고, 준비되면 다시 연결합니다. 연결되지 않은 이유는 오버레이 편집 화면의
키뷰어 예시에 표시합니다.

URL과 함께 받는 크기는 페이지 로딩 전의 초기값입니다. 로딩 후에는 키뷰어가
계산한 실제 키·통계·그래프·노트 트랙 영역을 사용합니다. 탭 전환, 키 개수나
배치 변경, 트랙 높이와 여백 변경 시 웹뷰를 자동으로 리사이징하고 저장한
위치 기준과 개별 배율을 유지합니다. 변경된 크기는 페이지 안에서 이벤트로
전달하며 주기적인 크기 측정이나 페이지 재로드를 하지 않습니다. 이후의
URL 확인 응답에 예전 데스크톱 창 크기가 포함되어도 현재 크기를 덮어쓰지 않습니다.

손·발 페이지는 각 뷰어에서 선택한 탭을 따로 사용합니다. 기존 설정과 초기화된
기본 배치는 게임 좌우 아래에 16포인트 간격으로 표시합니다. 연결 시 초기
뷰포트를 최대 430×270포인트에 맞춰 기본 배율을 한 번 정하고 유지합니다.
이후 콘텐츠의 가로·세로가 늘어나면 키 하나의 표시 크기를 유지한 채 웹뷰
영역 자체가 늘어납니다. 콘텐츠나 게임 창이 작아졌다는 이유로 별도의
자동 맞춤 배율을 다시 계산하지 않습니다.

키뷰어를 이동하면 중심에서 실제 게임 화면의 네 꼭짓점·중앙까지의 픽셀
거리를 비교해 가장 가까운 점을 고릅니다. 왼쪽 아래면 키뷰어의 왼쪽 아래를
고정하고 오른쪽·위로, 오른쪽 아래면 왼쪽·위로, 위쪽 두 꼭짓점이면 반대쪽
아래 방향으로 확장합니다. 중앙이면 현재 중심에서 사방으로 늘어납니다.
축소할 때도 같은 지점을 고정하며, 크기 변화 중에는 기준점을 다시 고르지
않습니다. 다시 이동하면 새 위치에서 선택합니다. 일반 Unity 오버레이의
9개 기준점 정책은 그대로 사용합니다.

편집한 키뷰어 배치는 이 5개 기준점 중 하나와 논리 단위 여백, 개별 배율을
저장합니다. 여백에는 실제 게임 화면의 너비·높이에 따라
`s = sqrt((너비 / 1920) × (높이 / 1080))`를 적용합니다.

크기는 별도 창 모드와 같습니다. 배율 100%에서 CSS 1픽셀이 macOS 1포인트,
Windows 1 DIP(창의 디스플레이 배율 적용)이므로 게임 해상도나 Retina 여부와
관계없이 ElementNote 창과 같은 크기로 보입니다. 네이티브 라이브러리가 알려 주는
게임 뷰 크기(포인트·DIP)와 Unity 화면 픽셀의 비율로 환산하며, 게임 창을 배율이
다른 모니터로 옮기면 그 모니터의 단위를 따릅니다. 처음 연결된 키뷰어가
430×270보다 크면 그 안에 맞는 배율로 시작하고, 편집 화면에는 별도 창 대비
배율이 표시됩니다. 저장한 배율이 게임 화면보다 크면 화면에 맞게 줄여 그리고
저장값은 유지합니다. 위치와 크기 변경은 로컬 프레임·페이지 배율만 갱신하며
IPC 요청이나 페이지 재로드를 발생시키지 않습니다.

## 캡처 호환성

| 캡처 | macOS | Windows |
|---|---|---|
| OBS 윈도우 캡처 | 포함 | 캡처 방식을 **Windows 10 (1903 이상)**으로 설정하면 포함. 기본값 **자동**은 Unity 창에 BitBlt를 골라 키뷰어가 빠짐 |
| OBS 게임 캡처 | 해당 없음 | 포함되지 않음 |
| OBS 디스플레이(화면) 캡처 | 포함 | 포함 |
| Discord 창 공유 | 포함 | 미확인 |

Windows의 키뷰어는 게임이 그린 프레임 위의 레이어로 합성됩니다. 게임 캡처와
BitBlt는 게임 프레임만 가져가므로 키뷰어가 빠집니다. 게임에 GPU 작업을 더하지
않기 위한 의도된 구조이며, 이 경로에 키뷰어를 넣으려면 완성된 이미지를 게임
프레임에 합성하는 별도 방식이 필요합니다.

## 빌드와 설치

저장소 루트에서 실행합니다.

```bash
./scripts/run.sh mod-check
./scripts/run.sh native-webview-check
./scripts/run.sh desktop-frontend-check
./scripts/run.sh desktop-native-check
./scripts/run.sh install
./scripts/run.sh desktop-bundle --release
```

모드 설치 후 게임을 재시작해야 새 DLL을 로드합니다. 실행 중인 게임은 기존
버전을 계속 사용합니다. 네이티브 라이브러리는 모드 폴더의
`native/libElementGameWebView.dylib`에 포함됩니다.

테스트 앱은
`apps/element-note/src-tauri/target/release/bundle/macos/ElementNote.app`입니다.
압축본은 `Release/ElementNote-Renderer-macos-arm64.zip`입니다.
기존 ElementNote 인스턴스를 종료한 뒤 이 앱을 실행합니다. 기존 앱 데이터와
프리셋을 사용하며 테스트를 위해 초기화하지 않습니다.

Release 앱을 사용해야 합니다. Debug 앱의 OBS 브릿지는
`http://localhost:3400/obs/index.html` 개발 서버로 리다이렉트하지만,
게임 웹뷰는 제공받은 OBS 서버와 같은 origin의 탐색만 허용합니다.
Release 빌드는 내장 프론트엔드를 OBS 서버에서 직접 제공하므로 Vite가 필요 없습니다.

### Windows

Windows 라이브러리(`native/ElementGameWebView.dll`)는 MSVC와 WebView2 SDK가 필요해
Windows PC에서 빌드합니다. OpenSSH 서버와 Visual Studio Build Tools(C++ x64)가
설치된 PC를 `.env`의 `ELEMENT_WINDOWS_HOST`와(필요하면)
`ELEMENT_WINDOWS_SSH_KEY`로 지정합니다.

```bash
./scripts/run.sh windows-webview-check  # 원격 빌드와 데스크톱 스모크 테스트
./scripts/run.sh windows-install        # 그 PC에 옮겨 설치할 zip 만들기(접속 없음)
```

`windows-install`은 그 PC에 접속하지 않습니다. 만든
`build/Element-windows-install.zip`을 그 PC로 옮겨 풀고, 게임을 닫은 채
그 폴더에서 `powershell -ExecutionPolicy Bypass -File .\Install.ps1`을 실행합니다.
`Install.ps1`은 Steam 라이브러리에서 얼불춤의 `Mods` 폴더를 찾고(다른 위치면
`-Mods <폴더>`), 설정 파일은 그대로 둔 채 모드를 바꿉니다.

빌드는 고정한 WebView2 SDK 1.0.4314.35를 NuGet에서 받아 SHA-256을 확인하고,
CRT와 WebView2 로더를 정적 링크해 시스템 DLL에만 의존하는 DLL을 만듭니다.
스모크 테스트는 로그인된 데스크톱에서 약 1분 동안 커서를 움직이고 자기 창을
클릭하므로 그 PC를 쓰지 않을 때 실행합니다. `package`는 현재 소스로 빌드하고
스모크 테스트를 통과한 DLL만 포함하며, 스모크 테스트를 직접 시작하지 않습니다.
소스를 바꿨다면 먼저 `windows-webview-check`를 실행하세요. 릴리스는 이 PC 대신
CD가 GitHub의 Windows 러너에서 빌드하고 스모크 테스트한 DLL을 씁니다
([릴리스](releasing.md)). CI도 PR마다 같은 빌드와 스모크 테스트를 돌립니다.
`ELEMENT_SKIP_WINDOWS_WEBVIEW=1`이면 Windows 라이브러리 없이
패키징하며, 이 경우 Windows 플레이어는 게임 내 키뷰어를 쓸 수 없습니다.
이 DLL은 `Element-windows.zip`에만 들어갑니다. 패키지에 함께 들어가는
ElementNote는 [모드에 포함된 ElementNote](bundled-element-note.md)를 보세요.
Windows용 ElementNote Release 빌드는 관리자 권한으로 실행됩니다.

## 사용하기

1. 업데이트된 ElementNote에서 손·발 뷰어의 원하는 탭·모양을 선택합니다.
2. 앱 설정에서 OBS 모드가 켜져 있는지 확인합니다(기본으로 켜져 있음). OBS Studio 자체를 실행할 필요는 없습니다.
3. 게임에서 왼쪽 Option + Tab(Windows는 왼쪽 Alt + Tab)으로 커스텀 설정을 엽니다. UMM의 **설정 열기** 버튼으로도 접근할 수 있습니다.
4. 첫 화면의 **Overlay**를 누릅니다. **Add Element** 갤러리에서 손 또는 발 키뷰어를 추가합니다. 갤러리는 예시 데이터로 미리보기를 표시하며, 실제 요소는 ElementNote에서 선택한 탭을 사용합니다.
5. 키뷰어를 선택해 이동·크기 조정합니다. 선택 전에는 현재 표시된 콘텐츠가 클릭 영역이고, 선택 후에는 최대 편집 영역에 흰색 점선이 표시됩니다. 내부는 이동, 네 꼭짓점과 네 변은 비율 유지 리사이즈 영역입니다. 앱의 바깥 여백을 뺀 콘텐츠 크기를 사용하며 노트 트랙 영역은 유지합니다. 화면 밖으로 이동하더라도 가로·세로의 10%는 남습니다.
6. 이동을 확정하면 가장 가까운 화면 기준점에 대한 여백을 저장하고, 크기 조절은 기존 기준점을 유지합니다. **저장**하면 요소 구성·기준점·여백·개별 배율을 유지합니다. **취소**하면 편집 시작 전 상태로 돌아갑니다. 플로팅 패널도 드래그할 수 있고, 점선은 패널 뒤에서 가려집니다.

기존 중심 좌표 설정은 먼저 기존 방식으로 표시하고, 해당 요소를 실제로 이동하거나
크기 조절할 때 현재 보이는 영역을 기준으로 전환합니다. 설정을 열거나 요소를
선택하기만 해서는 저장값을 바꾸지 않습니다. 초기화는 기본 배치로 돌아갑니다.
작은 화면에서 10% 가시성을 위해 임시 보정하더라도 저장된 여백과 배율은 유지합니다.
연결이 끊긴 상태의 편집 미리보기는 마지막으로 확인한 네이티브 콘텐츠 크기를 유지합니다.

같은 종류의 키뷰어도 여러 개 추가할 수 있으며 각 요소의 위치·배율을 따로 저장합니다.
손·발 키뷰어 요소가 하나라도 있으면 게임 내 키뷰어 연결을 사용하고, 모두 삭제하면
기능 자체를 비활성화합니다. 다시 추가하면 자동으로 연결을 재개합니다.
기존 설정의 **게임 내 손 · 발 키뷰어** 스위치와 연결·미리보기 카드는 제거했습니다.
이전에 키뷰어를 꺼둔 설정은 새 요소 구성으로 이전할 때도 유지합니다.

녹화 모드와 협동 모드에서는 일반 게임 표시를 숨깁니다. 오버레이 설정 중에는
미리보기를 임시로 표시하므로 플레이를 시작하지 않아도 배치할 수 있습니다.

## 직접 검증할 항목

| 항목 | 확인 방법 | 통과 기준 |
|---|---|---|
| 게임 창 내부 표시 | Overlay에서 손·발 요소를 추가하고 입력 | 각 뷰어가 해당 종류의 선택한 탭을 표시하고 입력에 반응 |
| 콘텐츠 크기 변경 | 발 2·4·8키 탭 전환, 키 배치·크기·트랙 높이 변경 | 키와 노트가 잘리지 않고 웹뷰가 확대·축소되며 저장한 위치 기준·배율 유지 |
