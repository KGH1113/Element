# 편집기 리디자인: 칸 · 값 · 입력기

2026-11-25, `feat/if-values`(76c0d291) 위에서 잡은 기획입니다. 대상은 텍스트 편집기와 도형 편집기이고, ElementKit의 모드 요소 편집기와 설정 창은 건드리지 않습니다.

**진행 (2026-11-26, `feat/editor-redesign`):** 1·2단계와 3단계 대부분이 들어갔습니다. 칸 모양, 줄의 제자리 펼침, 맞는 값만 보이는 목록, 지우기·적용, 끌어 놓기 없앰, 미리보기가 내용 칸(밑줄·타입표, 글자 값 안의 선택), 묶음이 있는 칸 목록, 불투명도 칸, 참·거짓 칸인 바뀔 때 커지기, 키패드 자리의 색 고르기, 색 목록의 그라데이션이 들어갔습니다.

계획과 달라진 점:
- 게임 글꼴 아틀라스에 ✱와 ⊡가 없어서 아무는 `*`, 자리(기준점)는 `⊙`로 씁니다.
- 내 값은 고르면 줄에 그 속이 펼쳐지고, 적용을 누르면 그 값이 있던 자리로 돌아갑니다. 이름은 입력기 자리에서 고치고, "안에 든 값 고치기"로 다시 엽니다.
- 폰트 목록(360×440)과 기준점 아홉 점(312 너비)은 키패드 자리보다 커서, 키패드 바로 위 칸 목록 자리에 엽니다("큰 입력기는 위로 자라요"). 그라데이션 도구도 같습니다.

남은 일: 내 값 지우기(쓰는 요소를 보여 주고 묻기, 취소하면 되돌리기), 바뀔 때 커지기에 조건 넣기(저장 형식에 칸이 필요), 이름표를 글 아래로.

눌러 보는 시안은 채팅 스크래치 폴더에 있습니다: `kan-redesign-4d9b.html`(문법과 틀), `kan-preview-7a2c.html`(미리보기가 내용 칸), `kan-editors-9c4f.html`(도형 편집기, 색 고르기), `kan-select-5b8d.html`(커서와 선택, 가장 최근).

## 왜 다시 하나

76c0d291은 "모든 입력은 타입이 있는 variable" 컨셉을 모델로는 옮겼지만 화면은 옛 문법 그대로였습니다. 써 본 평가는 이렇습니다.

- 칸에 값이 들어가고 타입이 무엇인지 화면만 봐서는 알 수 없다.
- "variable 안에서는 직접 입력할 수 없다"와 맞지 않는다. 글 본문은 커서를 두고 그대로 치고, 독의 줄은 계산기처럼 받아쓴다.
- 타입이 다른 값은 흐리게 할 게 아니라 보이지 않아야 한다.

그래서 틀(오른쪽 속성 기둥, 아래 독)은 두고 문법을 통째로 바꿉니다.

## 낱말 세 개

| 낱말 | 뜻 |
| --- | --- |
| 칸 | 요소의 속성 하나. 타입이 있고, 값만 담는다. |
| 값 | 칸에 들어가는 조각. 직접 만든 값(숫자, 글자, 색, 참·거짓), 게임이 알려 주는 값, 조건, 내 값. |
| 입력기 | 고른 값을 고치는 도구. 값의 타입마다 하나. |

타입과 타입표: 숫자 `#`, 글자 `가`, 색 `●`(그 색 그대로), 참·거짓 `◐`, 아무 `✱`, 폰트 `Aa`, 자리 `⊡`. 타입표에는 타입마다 옅은 색을 같이 씁니다(숫자 파랑, 글자 초록, 참·거짓 보라). 고른 것은 언제나 하이라이트 색입니다.

## 규칙

1. **칸은 어디서나 같은 모양이다.** 타입표, 이름, 든 값, 결과. 속성 기둥의 줄도, 도형 둘레의 너비 알약도, 조건 안의 자리도 같다.
2. **칸에는 값만 들어간다.** 글자도 값이다. 커서는 칸의 것이 아니라 글자 값의 입력기(키보드)의 것이라서, 글 안에만 있고 다른 칸에는 없다.
3. **목록에는 그 자리에 들어갈 수 있는 값만 나온다.** 제목이 타입을 말한다("숫자 칸에 넣을 수 있는 값"). 숨긴 값은 개수만 알린다. 고른 칸이 없으면 목록은 비어 있다.
4. **입력기는 항상 같은 자리(오른쪽 아래)에 나온다.** 고른 값이 없으면 쉰다.
5. **칸 안의 칸은 한 줄에 펼쳐 보인다.** 조건의 다섯 자리는 줄 안에 나란히 있고, 빈 자리에는 이름과 타입이 써 있다. 위로/안으로 이동은 없다.
6. **맞지 않는 값은 애초에 넣을 수 없다.** 남는 문제는 "비어 있음"뿐이고, 줄 아래에 바로 말한다.
7. **아무 칸만 값을 나란히 담는다.** 나머지 칸은 값 하나(숫자는 계산 하나)다. 그래서 한 자리 칸은 값을 고르면 바꿔 끼우고, 글은 커서 자리에 넣는다.
8. **연산 기호는 다음 숫자 자리를 데리고 온다.** `×`를 누르면 `× 0`이 생기고 그 0이 골라진다. 끊긴 식은 생기지 않는다.

## 텍스트 편집기

**미리보기가 곧 내용 칸입니다.** 독에 내용을 다시 늘어놓는 줄은 없습니다. 미리보기는 게임이 그리는 그대로여야 하므로 글자 위에는 아무것도 올리지 않고, 표시는 전부 글 아래에 둡니다.

- **밑줄.** 값 조각마다 얇은 꺾쇠 밑줄. 타입 색을 옅게 쓰고, 고른 조각은 하이라이트 색으로 굵게.
- **타입표.** 밑줄 가운데 아래에 작은 타입표.
- **이름표.** 조각에 올리면 그 값의 이름이 글 아래에 뜬다(지금의 값 이름 팁).
- **여러 줄.** 밑줄은 줄 사이 여백 안에 그린다. 타입표가 다음 줄 글자에 닿는 줄에서는 타입표를 그 조각에 올렸거나 골랐을 때만 보인다. 한 조각이 줄을 넘으면 줄마다 밑줄을 나눠 그리고 타입표는 마지막 줄에 둔다.
- **빈 글.** 커서와 옅은 안내("글자를 치거나 아래에서 값을 고르세요").

**텍스트 편집의 느낌은 그대로입니다.** 값을 넣는 + 단추는 두지 않습니다.

- **커서는 글자 값 안에 있다.** 글자 값이 옆에 있으면 커서는 그 안에 있고, 치는 동안 그 글자 값의 밑줄이 하이라이트 색으로 켜지고 같이 늘어난다. 글자 값이 없는 자리(값과 값 사이, 값 바로 뒤)에서 치면 첫 글자와 함께 새 글자 값이 생긴다.
- **값은 커서 자리에 들어간다.** 게임 값은 들어가고 커서가 그 뒤로 간다. 숫자·조건처럼 그 자리에서 만든 값은 들어가자마자 골라져서 아래에서 채운다. 글자 값 한가운데에 넣으면 그 글자 값이 둘로 나뉜다. 글에서는 목록에 "글자"가 없다(그냥 치면 되므로).
- **값은 글자 하나처럼 움직인다.** Backspace 한 번에 통째로 지워지고, 화살표는 한 번에 넘어간다.
- **선택은 글자 값 안에서만 된다.** 끌기, Shift + 화살표, Shift + Home/End로 고르고, 값을 넘어가지 않는다. 전체 선택(⌘A / Ctrl+A)은 커서가 있는 글자 값 전체다. 두 번 누르면 낱말, 세 번 누르면 그 글자 값 전체.
- **고른 채로 치거나 값을 고르면 그 자리를 바꾼다.** Backspace는 고른 글자를 지운다.
- **고른 글자만 꾸미면 그 부분이 따로 글자 값이 된다.** 모습 칸을 열 때 나뉘고, 아무것도 바꾸지 않고 닫으면 다시 합쳐진다. 꾸밈이 같은 글자 값이 붙어 있으면 언제나 한 값이다(저장 방식과 같음).

**고르는 것은 네 가지입니다.**

| 한 것 | 줄 | 목록 | 모습 칸의 대상 |
| --- | --- | --- | --- |
| 커서만 | 안내 | 커서 자리에 넣을 수 있는 값 | 글 전체 |
| 글자 선택 | 고른 글자 | 고른 글자 자리에 넣을 수 있는 값 | 고른 글자 |
| 값 조각을 누름 | 그 값의 속(숫자면 계산, 조건이면 다섯 자리) | 그 속에 넣을 수 있는 값 | 그 값 |
| 모습 칸을 엶 | 그 칸의 값들 | 그 칸에 넣을 수 있는 값 | (위 셋 중 하나) |

**칸 목록.** 대상의 모습(크기 `#`, 글자 색 `●`, 불투명도 `#`, 폰트 `Aa`, 바뀔 때 커지기 `◐`)과 요소의 기준점 `⊡`. 칸을 연 채로 글에서 다른 것을 고르면 그 대상의 같은 칸으로 넘어갑니다(지금의 "도구가 선택을 따라간다"와 같음). 연 칸을 다시 누르거나 적용하면 닫힙니다.

## 도형 편집기

- 도형 둘레의 **너비**(아래), **높이**(오른쪽), 네 모서리의 **둥글기**(호를 누르면 그 모서리 옆에 알약)가 모두 숫자 칸입니다. 알약은 타입표, 이름, 값(계산이면 결과를 하이라이트 색으로)을 보여 줍니다. 도형 위는 가리지 않습니다.
- 칸 목록: 채우기(색 `●`, 불투명도 `#`), 테두리(색 `●`, 두께 `#`, 불투명도 `#`), 요소(기준점 `⊡`).
- 고른 칸이 없으면 독은 쉽니다.

## 색과 불투명도

- 불투명도는 색 옆의 숫자 칸입니다(글자 색 옆 "불투명도", 채우기와 테두리마다 "불투명도"). 색 고르기 안의 불투명도 띠는 없어집니다.
- 그래서 색 고르기(네모, 색상 띠, HEX)는 키패드 자리에 들어갑니다. 입력기는 언제나 같은 자리입니다.
- 불투명도에 조건을 넣으면 값에 따라 사라지게 할 수 있습니다(Miss = 0 이면 100, 아니면 30).

## 넣을 수 있는 값

| 자리 | 나오는 값 |
| --- | --- |
| 숫자 칸, 계산 안 | 숫자·조건 만들기, 숫자인 게임 값, 숫자인 내 값 |
| 색 칸 | 커스텀 색·조건 만들기, 하이라이트 색, 색인 내 값 |
| 참·거짓 칸 | 참·거짓·조건 만들기, 참·거짓인 내 값 |
| 글의 커서 자리 | 숫자·조건 만들기, 숫자와 글자인 게임 값, 내 값 |
| 글 안 조건의 결과값·기본값 | 위와 같고 글자 만들기도. 자리 끝의 +로 넣는다(커서가 없는 자리라서) |
| 조건의 비교할 값·비교 당할 값 | 숫자 칸과 같음 |
| 조건의 비교 기호, 연산 기호 | 목록 없음. 입력기에서 고른다 |
| 폰트·기준점 칸 | 목록 없음. 입력기에서 고른다 |

값이 하나도 없는 분류는 보이지 않습니다. 검색도 들어갈 수 있는 값만 찾습니다.

## 입력기

| 고른 값 | 입력기 |
| --- | --- |
| 숫자 | 키패드(숫자, 점, 지우기, + − × ÷) |
| 숫자인 게임 값 | 키패드에서 연산 기호만 |
| 글자 | 키보드. 글에서는 그 자리에서 치고, 조건 안의 글자는 입력기 자리의 칸에 친다 |
| 커스텀 색 | 색 고르기(네모, 색상 띠, HEX) |
| 하이라이트 색 | 설정을 따라간다는 안내 |
| 참·거짓 | 참 / 거짓 두 단추 |
| 조건 | 안내(자리는 줄에서 누른다) |
| 비교 기호 | < ≤ = ≠ ≥ > |
| 연산 기호 | + − × ÷ |
| 폰트 | 폰트 목록 |
| 기준점 | 아홉 자리와 자동 |
| 글자인 게임 값 | 지금 읽는 값 안내 |

입력기 아래에는 언제나 **지우기**(고른 값)와 **적용**이 있습니다. AC와 위로는 없어집니다.

## 끝낼 수 없을 때

- 빈 자리는 그 타입 모양의 빈 자리로 보이고, 줄 아래에 어느 자리가 비었는지 바로 나옵니다("조건의 결과값 자리가 비어 있어요. 값을 넣어 주세요.").
- 적용은 그 문장을 다시 말하고 닫지 않습니다. 요소는 그동안 전에 가진 것을 보여 줍니다.
- 글 안 조건의 결과값·기본값은 비워도 됩니다(아무것도 안 보임).

## 저장 형식

- 글은 지금도 꾸밈이 같은 글자끼리 한 런으로 저장합니다. 런 하나가 조각 하나가 되므로 저장된 글은 모양 그대로 옮겨집니다. 꾸밈이 같은 글자 조각 둘이 붙어 있으면 다시 열 때 한 조각이 됩니다(구현 때 확인).
- 바뀔 때 커지기에 조건을 넣으려면 런에 식을 담을 자리 하나가 더 필요합니다. 더하는 필드뿐이라 설정 버전은 10 그대로일 것으로 봅니다.
- 내 값, 조건 문법(`if(…;…;…;…;…)`)은 76c0d291 그대로 씁니다.

## 아직 안 정한 것

1. **그라데이션.** 색 값의 한 종류로 목록에 넣을지(하이라이트 색 / 커스텀 색 / 그라데이션 / 조건). 색 정지점의 위치와 불투명도는 그 입력기 안의 숫자 칸이 됩니다.
2. **값 끌어다 놓기.** 남긴다면 놓는 곳은 글의 커서 자리와 칸뿐입니다. 넣는 길을 하나로 하려면 없앱니다.
3. **게임이 알려 주는 색과 참·거짓 값.** 판정 색, "오토플레이 중" 같은 값이 있으면 색 칸과 참·거짓 칸의 목록이 덜 비어 보입니다.
4. **내 값 고치기와 지우기.** 내 값의 속은 줄에 펼치지 않고 따로 엽니다(모든 요소가 같이 쓰는 값이라서). 지우기는 아직 없습니다.

## 만드는 순서(제안)

1. 문법 부품: 칸 줄(타입표와 값), 숨기는 목록과 제목, 줄에 펼친 조건, 숫자 자리를 데리고 오는 연산 기호, 지우기 · 적용 줄. 본문이 없는 도형 편집기에 먼저 붙입니다.
2. 텍스트 미리보기를 내용 칸으로: 글 아래 밑줄·타입표 층, 글자 값 안의 커서와 선택, 고른 글자만 꾸미기, 커서 자리에 값 넣기.
3. 모습 칸: 커지기를 참·거짓 칸으로, 폰트와 기준점을 칸으로, 불투명도를 따로 칸으로, 색 고르기를 키패드 자리로.
4. ui-check 시나리오를 새 흐름으로 다시 쓰고, `docs/features/overlay-elements.md`를 고치고, 설치합니다.
